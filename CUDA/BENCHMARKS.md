# Benchmarks

Append-only measurement log. **Never edit or delete an existing entry.** A
regression is only visible if the number it regressed from is still here, and by
week 12 this file is most of the write-up.

Entries are generated by the benchmark runner itself:

```bash
cuda bench --markdown CUDA/BENCHMARKS.md --note "what changed"
```

## Methodology

Every entry in this file was produced under these rules. Where a run violated
one of them, the entry says so explicitly rather than quietly omitting it.

- **Release build only.** Debug builds compile device code with `-G`, which
  disables essentially all optimisation. The runner refuses to call a Debug run
  trustworthy.
- **CUDA events, not wall clock.** Kernel launches are asynchronous, so host
  timing measures the driver, not the GPU. Events are recorded into the stream
  and timestamped by the device.
- **Warmup discarded.** 25 untimed iterations before any measurement, so the
  first-launch context setup and clock ramp are not in the sample.
- **Distributions, not single numbers.** 200 timed iterations per configuration;
  median is the headline, p99 shows the tail, and the coefficient of variation
  says whether the machine was quiet enough to believe either.
- **Clock state recorded.** SM and memory clock, temperature and NVML clock-event
  reasons are sampled either side of every measured run and written into the
  entry. A number without its clock state is not reproducible.
- **Correctness before timing.** Each kernel is verified against the expected
  result before it is measured. A fast wrong kernel is worth nothing.

**Bytes moved** for `vector_add` are counted as two reads plus one write per
element, `3 * n * 4` bytes. Rates are derived from the median.

**Theoretical bandwidth** for this card is 272.0 GB/s: 8501 MHz memory clock,
x2 for DDR, over a 128-bit bus. That is the ceiling; the recurring question for
every kernel in this project is how close it gets and, when it is far, why.

## 2026-09-08 - vector_add bandwidth baseline

**What changed:** Week 1 baseline. First benchmark harness run: CUDA event timing, warmup, median/p99 over 200 iterations, NVML clock state. Clocks NOT locked.

**Hardware:** NVIDIA GeForce RTX 4060 (sm_89, 24 SMs, 128-bit @ 8501 MHz), 8.0 GiB global, 24.0 MiB L2. Theoretical bandwidth 272.0 GB/s.

**Clock state:** SM 2790 MHz, MEM 8251 MHz, 53 C, power n/a, limiters: none

**Build:** Release x64, MSVC 1951, CUDA runtime 13.3, sm_89, -lineinfo, no fast-math.

**Method:** CUDA events around each individual launch. 25 warmup iterations discarded, 200 timed iterations retained; rates derived from the median. Bytes moved counted as 2 reads + 1 write per element.

|---|---|---:|---:|---:|---:|---:|---:|

| `v2_float4` | n=1Mi \* | 0.0113 | 0.0224 | 0.0102 | 1117.1 | 410.6% | 34.12% |
| `v1_scalar` | n=4Mi | 0.2032 | 0.2365 | 0.1731 | 247.7 | 91.1% | 3.74% |
| `v2_float4` | n=4Mi | 0.2028 | 0.2344 | 0.1843 | 248.2 | 91.3% | 3.12% |
| `v1_scalar` | n=16Mi | 0.8100 | 1.7234 | 0.7926 | 248.6 | 91.4% | 19.80% |
| `v2_float4` | n=16Mi | 0.8160 | 1.7838 | 0.7905 | 246.7 | 90.7% | 19.19% |
